# 《楚物志 · 数字版》客户端

本项目是荆楚非遗主题桌游《楚物志》的 Godot 数字孪生版本，由华中科技大学新闻学院和法学院联合项目组开发。

当前版本：**beta 0.5.0**（Godot 4.7；本地验证及 CI 固定 4.7.2）

当前实现、验证范围和待办统一见[项目现状与已知问题](docs/项目现状与已知问题.md)。AI策略v4完整矩阵尚未完成，保留772局、剩4196局，不拼接旧版本结果。

AI批次入口为`python tools/verify_ai_difficulties.py`；开发诊断使用启动参数`--ai-trace`，离线重放入口为`tools/replay_ai_decisions.gd`，均无局内入口。

短入门入口：**开始游戏 → 教学模式**。固定使用生活博主，跟随旅行博主完成移动、收集、补给、认识传承、查看计分与结束回合。练习不写正式图鉴，传承环节明确为教学示意，不打开操作小游戏。详见[短入门教程实施记录](docs/项目现状与已知问题.md)。

通用设置入口：**首页右上角“设置”／局内暂停 → 设置／小游戏设置 → 通用设置**。提供声音、画面和辅助三页，本机自动保存；切换显示模式有15秒还原确认。详见[通用设置实施记录](docs/项目现状与已知问题.md)。

## 当前功能

- 新版开局流程：首页选择模式，设置真人与电脑人数，再逐位设置名字、职业和出生点，经阵容总览确认后进入对局。
- 1–6 人本地回合制对局，包含 2D6 移动、精力路径、回合末淘汰、15/20/25/30 分目标与累计淘汰 2 人的终局判断。
- 完整地图交互：全局/追踪视角、拖拽缩放、地块信息、风景、打工、商店、非遗点、事件格和四个共享研究所入口。
- 非遗牌收集、使用、转移、研究所买卖、动态组合计分和牌区提示；15 张国家级非遗通过独立传承任务解锁分数与组合资格。
- 60 张统一食物牌库（20 市级、36 省级、4 国家级）及其个性化效果、持续状态、多人响应和回库流程。
- 40 张事件牌、保留事件牌、地图选格/选人、响应链、超时裁定和研究所事件。
- 六种职业技能、六项本局成就，以及分项揭晓、排名重排和冠军展示的正式结算界面。
- 统一的卡牌获得、失去和转移动画，以及棕金色弹窗、简洁提示和右侧手牌 HUD。
- 共用的数字版游戏指南：六步快速上手、分层规则介绍、中文搜索、情境跳转与响应式导航。
- 本机共享探索图鉴：非遗、职业和风景公开，食物、事件和成就在游戏中首次公开后永久翻开；从主菜单还可重玩已经发现的传承小游戏。
- 15 项国家级非遗传承小游戏正在完成全面重构：木壳电视、清晰中文、教学顶条、可重绑定输入与六位博主外观；故事改三幕滑块拼图，剪纸改同图四处纹样，董永推车越坡桥，神舟三道控速护送。五个表演音游使用连续原声，鼓盆歌保留示范—复现；程序验证、画面检查与用户体验验收分别记录。

本地游戏至少需要 1 名真人玩家，总人数不超过 6 人。每个电脑席位可单独选择简单、普通或困难，默认普通；电脑传承成功率分别为60%／80%／100%。顶部“AI速度”按钮按1.00／1.50／2.00／3.00倍循环切换，难度与演出速度独立；网络游戏暂未开放。教学模式已接入一段无操作倒计时的短入门。

最终传承任务美术、全局音效/BGM、网络游戏仍需继续完善；电脑挑战性另需试玩验收，旧 Demo 说明不作为当前规则依据。数字版相对纸质说明书的变化见 `docs/游戏说明书（数字版变更记录）.md`。

小游戏当前实现、素材与验证见[项目现状与已知问题](docs/项目现状与已知问题.md)。人物与场景使用直接生成原稿；用户已认可的神农原图保留五官、颜色与动作细节，不再压成20×24、16色再放大。当前是工程试看，不制作给美术的ZIP。音乐混音仍需逐句听审，普通输入自动通关不代表真人体验已验收。

目录整理、保留成果和恢复凭据见[本轮清理记录](maintenance/cleanup-20260916/验收与清理结果.md)。最新参赛成果在本机`deliverables/`，不纳入Git；原始录像已回收，剪辑工程需重新录制素材才能再次渲染。

兴山主鸟控制、糖塑余胀与评分、黄梅戏录唱评分保留已认可的核心规则。当前玩法与真实素材缺口统一记录在[项目现状与已知问题](docs/项目现状与已知问题.md)，早期阶段方案不覆盖后续确认。

## Beta 验证

完整验证入口：

```powershell
./tools/verify_beta.ps1 -GodotPath "路径\Godot_v4.7.2-stable_win64_console.exe"
```

该命令先校验指南 Markdown 与运行时目录完全同步，再执行干净导入、主场景启动、两局真实前端点击与完整回合、全部 GUT 测试，以及 2/3/6 人三种策略的 9 局模拟冒烟。测试数为零、非预期引擎错误、对象/资源泄漏、旧报告冒充新结果、缺少正式终局或遗留交互状态都会使验证失败。运行前应关闭正在占用本项目的 Godot 编辑器。

三档电脑 AI 的批次验收使用`python tools/verify_ai_difficulties.py`，覆盖4968局稳定性与难度对抗，默认两个进程；另运行上述Beta入口以及`tools/ai_difficulty_gui_review.tscn`的开局界面检查。三档响应检查使用`tools/ai_interaction_gui_review.tscn -- --difficulty=0`（依次替换为1、2）。批次期间不要同时启动大量GUI或完整Beta进程，以免耗尽测试机内存。

原单档电脑 AI 验证入口继续保留，用于普通AI与旧策略对照回归（Beta、972局普通AI、324局旧策略对照及GUI检查）：

```powershell
./tools/verify_ai.ps1 -GodotPath "路径\Godot_v4.7.2-stable_win64_console.exe"
```

可用 `-SkipBeta` 或 `-SkipGui` 只跑相应范围，报告须注明跳过项。AI原始结果、代码哈希和统计写入 `artifacts/ai-*.json`；实现、实际验证与体验边界见[电脑AI接入与验收](docs/项目现状与已知问题.md)。

旧三策略的 972 局对照批次（不使用正式电脑AI）：

```powershell
./tools/run_balance_simulation.ps1 -GodotPath "路径\Godot_v4.7.2-stable_win64_console.exe"
```

结果写入被 Git 忽略的 `artifacts/`；每个失败种子均保留终止原因、最后状态和交互快照。详见 `docs/Beta稳定性与平衡测试.md`。
