## 最新优先规则：改用 imagegen 原生生成（2026-09-13，取代下方旧流程）

用户已明确放弃 Aseprite 绘制方法。**后续人物、器物、整条动作动画和背景统一改用 imagegen 原生生成与修改。** 本节优先于下文全部 Aseprite / Lua 制作、固定色板和强制导出要求；文件保留在原路径只是为了交接，不代表继续采用旧生产方式。

- 已保存的 `.aseprite`、Lua、PNG、图集和审稿预览保留归档，不覆盖、不删除。未通过的 r2 / r3 候选不能自动接入正式资源；不得再执行旧 Lua 批量扩展人物、动作或十五关资产。
- 先读原博主立绘和可靠器物参考，再生成。人物必须保留各自的发型、脸型、眼睛、年龄感与服装辨识点；不套共用圆脸，不把机械缩小原图当成新成品。原立绘不修改。
- 先在实际镜头中确定人物、器物、背景和 UI 的位置与比例。沿用当前 500×300 原生舞台的展示约定，输出整理到同一像素密度；人物不能比环境显著粗糙，背景也不能靠密集杂点表现精细。使用有限、协调的色彩和连续色块，不逐帧任意换色；旧 48 色母板、角色 16 色或 22–24 色试稿预算均不能强行覆盖新方案。
- 动画围绕一个动作，以 **whole-strip（整条动作序列）** 为单位生成，固定画布、朝向、角色比例、服装、光照、帧顺序、接触锚点与色彩。先确认预备、接触、发力、收势的动作因果，再完成连贯中间帧；不把逐帧独立生成的人物直接拼成正式动画。
- 手与风箱、弓、刀、车把等器物的接触必须连续；脚要交替承重，身体发力要带动相应关节。人物、器物和特效应按实际遮挡关系分层；静态背景、砖口和平台不随动画抖动。不能以整人缩放、歪脖或整炉晃动替代动作。
- 保留原始生成结果、提示词、参考用途、版本、切片规则、帧时长与锚点。透明主体须检查黑底、白底和实际背景；发现脏边、形体漂移或接触错误，回到生成结果作有针对性的修改。切片、格式转换和统计是整理手段，不是用旧手绘管线重造角色的入口。
- 逐帧检查和正常速度实际播放继续是验收要求：看原生尺寸、整数倍放大、首尾接缝、发型与五官稳定性、手脚接触、材质闪烁及完整场景。只生成 GIF、联系表或通过尺寸统计，不等于已经看过动画；未实际播放的部分须明确列为待审。
- **Aseprite、Lua、linked cels、索引色板检查和 Aseprite CLI 导出不再是生产或验收的强制门槛。** 原软件和旧源保留即可，无需安装或卸载；可编辑信息通过生成原稿、图层/序列拆分、元数据与运行资源留存，不要求先补 `.aseprite` 才能交付新候选。

## 1. 在同一画面里确定尺寸与色彩

游戏画面使用500×300原生像素网格。角色、前后景、器物、地表在该网格里以1素材像素对应1舞台像素显示；1000×600逻辑坐标的换算在表现层统一处理，不对每张PNG分别随意缩放。镜头变化可以让人物更大，但同一镜头中的人物、器物和环境必须共用尺度。

先做完整构图：人物、接触器物、实际可操作区域、HUD与教学提示全部放入画面。单独漂亮的角色设定板不能代替实际背景里的协调性。500×300不是把高分辨率AI画缩小后的验收尺寸；最终曲线、色块和细节都要在该原生网格上修整。

当前母板为 `InheritanceTasks/Art/Pixel/v2/palette.json` 的48种明确颜色。背景/整套静态场景从中取色；普通角色当前预算为16色，小器物12色，UI资产16色。复杂戏服若确实需要扩展，应在该资产规范中明确理由与上限，不能逐帧自动增加近似色。所有帧共享同一颜色索引含义，不对每帧独立量化。

先画剪影、再画大色块、最后加必要细节。脸、头发、袖口和器物不以大量孤立像素制造质感。材质与轮廓必须服从同一光照与配色：冷暖不是固定公式；画面需要炉火等第二光源时，人物和环境一起表现。少数眼睛、扣子、高光可以使用单像素，逐个说明其视觉用途，不用自动去噪破坏识别点。

## 2. 可编辑源文件与动作

人物和关键器物直接在透明图层绘制。禁止先画绿幕人物再靠阈值抠图交付；禁止把旧抠图硬化alpha当作边缘修复。人物轮廓使用二值透明；烟、光束、糖膜等需要透明度的效果另设资源并明确登记。

`.aseprite` 是可编辑源，保留图层、帧、时长、tags与slices。Lua可以生成基础结构或修改指定区域；后续修改应保留已经认可的像素，避免每帧重画导致发型、脸型、衣褶及器物形制漂移。Aseprite的linked cels适用于静态部件，动作部位用独立关键帧。

先完成动作的关键姿势，再补中间帧。跑步至少要明确左右接触、承重、通过、抬起的关系；左右腿确实交替，足底与地面一致。手必须接触琴弓、刀、吹管、车把或风箱把手；袖口、发型、前景遮挡要在全部角色中逐帧检查。不能以整个人物缩放/晃动代替拉、推、吹、敲、落步等动作。

固定背景、台阶和底座不随动画帧改变。不能为了让画面“活起来”让地面一直闪动。角色图集完整帧尺寸和锚点固定；不要按每帧内容重新裁切、缩放、居中。动作必须有接触帧与收势，循环末帧到首帧也要连贯。

## 3. 实际绘制、导出与自动检查

当前工具链见 `README.md` 和 `toolchain-lock.json`。`draw_p1_assets.lua` / `pixel_drawing.lua` 是P1画稿与绘图辅助，使用前读取正在工作的部分；不能把示例中的当前帧数当成所有后续关卡的固定限制。

运行 `export_p1_assets.py` 通过真实Aseprite CLI导出同相对路径的PNG及JSON。检查固定帧尺寸、颜色索引范围、二值透明、帧数、动作标签、切片/锚点，以及源文件/导出文件哈希。报告写入 `artifacts/pixel-v2/`。

动作差异数字只用于找可疑帧。相邻帧完全相同可能是有意停顿，也可能根本没画动作；差异很大可能是正确的快速动作，也可能是人物漂移。必须结合播放判断。颜色预算检查是最低一致性检查，不能证明轮廓、配色、构图或文化形制正确。

Pillow可读取PNG、统计像素、拼接预览；当前生产主工具是Aseprite，不把Pillow重新画出的图冒充Aseprite逐帧源文件。输出运行PNG时不使用模糊插值、自动抖色或不可控重采样修饰缺陷。

## 4. 每次视觉审查应实际覆盖什么

1. **原生与放大：**看1倍图与整数倍最近邻放大，既检查整体轮廓，也检查连续色块、轮廓台阶和孤立杂点。
2. **黑底、白底、实际底：**把透明主体放在三类底色上，检查残边、错误透明、背景透色及色彩冲突。不能只在接近衣服颜色的底上看。
3. **完整场景：**人物、地面、器物、场景光照与UI同屏，确认像素密度一致、角色比例合适、交互部位突出，文字不挡手、脚和目标。
4. **正常速度与慢看：**动作按游戏实际时长至少播放完整循环，重点看首尾接缝、脚底滑动、手与物体脱离、发型抖动及材质闪烁；慢速逐帧检查用于定位问题，不能代替正常速度播放。
5. **六位身份：**对应镜头下逐个检查发型、脸部辨识、袖口与持物遮挡。共用动作结构不等于六个角色都已检查。
6. **当前工程：**在实际背景、操作速度和目标窗口尺寸下观察准备、关键操作、失误恢复及结果。截图摆拍、强制结果与自动输入分别标明；不能把它们算成用户体验验收。

审查记录必须写明发现了什么、改了什么、哪些画面实际看过、哪些动作仍需再看。只列“通过色数检查”“截图已生成”不能标记美术完成。若画面仍显得比例错误、死板或难辨认，即使所有数字通过也继续修正。

## 5. UI、文化与交付边界

UI和小游戏素材一起设计：母板、边框厚度、按钮状态、字体尺寸、焦点和按键图标构成一套体系。中文正文保持足够实际物理尺寸；不为了复古把文字压得过小。当前阶段是否允许扩大到全十五关，按用户的样板反馈和授权范围执行。

戏服、乐器、神舟、鼓板等有真实形制的内容先核对可靠资料。引用图片只承担其声明的用途；演奏动作中推演的部分单独标明。绘制可编辑素材不自动解决文化正确性问题。

源资产、运行导出、规范、来源和版本分别留存。可以交付自有`.aseprite`与Lua；不可将Aseprite编辑器二进制随游戏或美术包分发。
