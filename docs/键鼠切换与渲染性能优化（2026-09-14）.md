# 键鼠切换与渲染性能优化（2026-09-14）

用户反馈上一轮仍卡顿后，本轮继续修改了当前工程。先前短时间、独立 Host 的性能记录不足以证明真实图鉴入口流畅。本轮采样改用主菜单→小游戏图鉴→正式练习 Host，`test_mode=false`，实际跳过教学并进入 LIVE 后才计量。

## 本轮修改

- 设备切换只更新当前可见提示。准备、暂停页面在重新显示时更新；隐藏提示不再播放按压动画。图标槽宽固定，键鼠/手柄切换不反复挤压文字。
- 像素字体、源纹理、缩放后的 UI 纹理及 StyleBox 复用，取消纹理缓存达到 72 项后整体清空的行为。显示图标不再重新创建字体和上传 UI 纹理。
- 动作提示模板按设备缓存，按住状态仍从各物理来源汇总。纯鼠标移动走短路径，不做键盘绑定和菜单动作扫描；已是鼠标提示时不重复累计切换阈值。
- 练习中隐藏被电视完全覆盖的图鉴内容，保留图鉴节点、导航位置与生命周期；返回时立即恢复。隐藏的图鉴也不再处理缩放刷新。
- 默认渲染改为 Compatibility/OpenGL。素材原色、源帧清晰度、逻辑尺寸、120Hz 物理与音乐评分保持不变。当前工程主要为 2D CanvasItem；已检查主地图、棋子、前端和小游戏实际画面。旧 EXE 与正在运行的旧进程不会自动获得该设置。

没有改动正式成本、尝试、解锁与黄梅戏录音流程。本轮不录麦克风、不导出美术 ZIP。

## 性能证据和范围

设备为本机 RTX 4060 Laptop GPU、NVIDIA 610.88、Godot 4.7.2。报告在 `artifacts/performance-gallery/`，工具为 `tools/profile_minigame_gallery.gd`。

- 每个分辨率测神农、炼丹、花鼓戏；每关预热后 4 秒键盘、8 秒交替输入。交替段每 100ms 切换输入源，并附每帧八次鼠标移动事件，包含手柄按钮模拟。
- 最终三尺寸共 18 段，其中九段交替输入共 72 秒、531 次设备切换。全部处于正式 LIVE，未暂停、未使用测试模式；采样期间不截图、不读回 GPU 图像、不并跑测试。
- `final.json` 保存原始逐帧墙钟时间、输入处理耗时、绘制调用及资源计数。下表是交替输入段，不是玩家完整通关记录，也不是用户手感验收。

| 窗口 | 关卡 | P95帧时间(ms) | P99帧时间(ms) | 最慢一帧(ms) |
|---|---|---:|---:|---:|
| 1280×720 | 神农 | 14.204 | 16.764 | 20.384 |
| 1280×720 | 炼丹 | 14.306 | 17.084 | 27.538 |
| 1280×720 | 花鼓戏 | 14.026 | 16.504 | 23.409 |
| 1920×1080 | 神农 | 14.163 | 16.309 | 21.840 |
| 1920×1080 | 炼丹 | 14.279 | 16.451 | 19.711 |
| 1920×1080 | 花鼓戏 | 14.495 | 17.147 | 21.119 |
| 2560×1600 | 神农 | 14.301 | 16.651 | 19.672 |
| 2560×1600 | 炼丹 | 14.645 | 16.513 | 26.462 |
| 2560×1600 | 花鼓戏 | 14.404 | 16.953 | 25.231 |

这些采样段新增提示行、偏好配置读盘、UI 纹理上传、像素字体创建均为 0；没有超过 33.3ms 或 50ms 的单帧。这里只覆盖预热后的选定段落，不覆盖首次媒体载入、其他所有关卡或其他硬件。主循环采样帧数不等于屏幕上产生了同等数量的独立动画帧，不能按平均主循环帧率宣传“200FPS”。

同一 OpenGL 实际入口基线 `before-gl-live.json` 与第一轮修改 `after-gl-live.json` 对照：1920×1080 下，神农交替段绘制调用中位数由 150 降到 48，炼丹 140→38，花鼓戏 144→42。减少主要来自停止绘制被完全遮盖的图鉴。仅这组缓存/UI 改动的整体帧时间提升并不稳定，不能把绘制调用下降约七成说成帧率提升七成。

第一轮 UI 修改后另测 `after-d3d-live.json`；1920×1080 下三个关卡的交替段 P99 为约 20–22ms，同阶段 OpenGL 较低。因此本机当前 2D 工程改用 Compatibility。初始 D3D12 未完成稳定的修改前采样，不计算“D3D12 修改前后提升百分比”。`before-gl.json` 是误测教学的早期工具稿，不参与正式比较；`after-gl-live.json` 最后一个片段与测试重叠，不作最终性能结论。

## 回归和画面

- 新渲染模式下真实前端指针操作连续开两局、地图交互和会话清理通过，见 `frontend-render.log` 的 `FRONTEND_SESSION_E2E: PASS`。
- 实际画面保存在 `map-1.png`、`map-2.png`、`screens/`；已查看地图、两位职业、1280 准备页和神农奔跑，另有三个尺寸准备页、教学、大倒数、跳跃及神舟截图。未发现本次渲染变更造成的这些画面缺失；不是全部十五关/六角色美术验收。
- 本轮没有重跑完整 Beta 和九局模拟；上一轮 688 项与九局模拟属于此前实现的记录，不计为本轮验证。

## 当前试玩与后续定位

`tools/preview_heritage_performance.gd` 打开实际主菜单小游戏图鉴，仍只在当前进程显示全部关卡。玩家正常操作时只在内存采样帧时间、阶段和设备类别；不记录具体按键内容、不采集声音。返回图鉴时保存到 `artifacts/performance-gallery/user-play.json`，操作期间不逐帧写盘。直接关闭整个窗口未必保存当前未返回的局。

此入口用于定位用户仍遇到的具体卡顿，不把有限自动采样作为“所有卡顿已经消失”的承诺。当前用户尚未反馈本轮优化后的实际手感。
