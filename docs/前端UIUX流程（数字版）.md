# 《楚物志》前端 UI/UX 流程（数字版）

适用版本：`beta 0.3.0`

本文档规定从启动游戏到进入正式对局的页面流、输入、焦点、开局数据和兼容接口。本阶段优先保证操作清晰、状态可恢复及鼠标、键盘、单手柄均可完整操作；现有棕金色素材和职业立绘仅作为临时视觉。

## 标准页面流

```text
首页 → 模式选择 → 真人/电脑人数 → 逐位配置 → 阵容总览 → 加载 → 对局
```

### 首页

首页保留“开始游戏”“游戏说明”“制作人员”“退出游戏”。游戏说明与制作人员是真正的模态页：打开时锁定背景操作，关闭后将焦点还给原入口。本阶段不改写两页的原有文字内容。

从后续开局页返回首页时：

- 未开始配置玩家则直接返回。
- 已有配置草稿则询问是否放弃；确认后清空草稿，取消后保留草稿并停留当前页。

### 模式选择

显示“本地游戏”“网络游戏”“教学模式”。

- 本地游戏进入人数配置。
- 网络游戏和教学模式按钮可聚焦、可点击，点击时发出模式请求信号并显示“暂未开放”，不进入空白页。
- 预留的模式请求不得建立未完成的网络会话或教学对局。

### 本地人数

使用两个步进选择器：

- 真人玩家最少 1 人。
- 电脑玩家最少 0 人。
- 总人数为 1–6 人，不允许超过 6 人。

界面实时显示总人数，边界上的增减按钮必须禁用。席位顺序固定为先排真人、再排电脑。本阶段电脑玩家只是席位类型，仍由同一台设备顺序操作，不实现 AI 或独立控制器分配。页面只显示简短提示“电脑玩家暂由本地操作”。

调整人数后保留仍然存在的席位配置。新增电脑席位自动生成默认配置；删除未配置的尾部席位直接生效，删除已配置的尾部席位前需要确认。

### 逐位配置

每次只配置一个席位，按 P1 至 P6 的实际席位顺序进行。页面顶部显示席位编号、“真人”或“电脑”标记及“2 / 4”形式的进度。

职业与角色继续绑定，不新增独立角色选择。六个职业以 `2 × 3` 卡片网格呈现：

- 选中卡片后显示更大的角色立绘、职业名、技能名和技能描述。
- 技能信息始终可见，不依赖鼠标悬浮才能阅读。
- 已被占用的职业仍可聚焦和查看，但不可确认，并以“P1 已选”等文字指明占用者。
- 真人席位不自动确认职业；电脑席位默认使用稳定顺序中第一个未占用职业，但允许修改。

同一页完成名字、职业和出生点：

- 名字支持键盘输入；留空确认时使用 `P1`、`P2` 等默认名，允许玩家重名。
- 手柄流程可保留默认名，不强制进入文字输入。
- 电脑席位默认命名为“电脑1”“电脑2”等，并自动选择第一个未占用职业和出生点；三项均可修改。

职业和出生点在一局内均为全局唯一。名字不参与唯一性校验。

出生点使用“湖北简图热点＋同步列表”：

- 鼠标可直接选择地图热点，键盘和手柄通过列表稳定导航。
- 热点和列表共享同一当前选择。
- 已占用的地区仍可聚焦查看，但不可确认，并标明占用者。
- 真实出生坐标只取自 `MapSection.出生点坐标`；简图热点只保存 UI 显示位置，不复制规则坐标。

只有当名字已经按默认规则补全、职业和出生点均合法时，“确认”才会进入下一位。返回上一位保留草稿。从阵容总览进入编辑时，重新确认后应回到阵容总览。

### 阵容总览

所有席位配置后进入“全员就绪舞台”，不再使用同质化的信息表格。页面视觉层级固定为：全员就绪状态、玩家角色与姓名、职业和出生点、真人/电脑等辅助信息。

每张席位卡使用稳定的 P1–P6 识别色，并同时显示玩家编号，不能只依赖颜色区分。角色立绘是卡片主视觉；真人席位不显示类型标签，电脑席位仅标记“AI”；“就绪”使用短徽标，不能再用整卡绿色底板表达确认状态。立绘下方以横向双栏显示信息：左侧突出名字，右侧只显示职业和地区名，不增加“出生”等冗余前缀。聚焦或悬浮席位时，下方预览条显示该玩家的职业技能与地区。

阵列随人数调整：1 人居中，2 人左右对称，3 人单排，4 人为 2×2，5–6 人为 3×2。少人数时不得把单张卡拉满整个内容区。

- 点击任意玩家卡可编辑该席位。
- 只有整份开局数据校验通过时才可开始。
- 快速重复点击、按 Enter 或重复手柄确认只能创建一次会话。

### 加载与进入对局

开始后先显示“准备中”并渲染至少一帧，再执行同步资源重置和会话准备。加载页不显示虚假百分比。

加载期间锁定返回与重复开始。准备成功后进入对局；准备失败时解除锁定、返回阵容总览并显示简短错误。这一流程用于避免同步重建牌库时先进入半初始化对局界面。

## 输入、焦点与反馈

全流程必须支持鼠标、键盘和单手柄，不做多手柄绑定。

- 每个页面显示时设置明确的初始焦点和四向焦点邻接。
- `ui_accept` 用于确认，`ui_cancel` 用于返回或关闭最上层模态。
- 模态打开时焦点不得离开模态，关闭后恢复原入口。
- 隐藏页、已删除席位和被背景锁定的控件不得持有焦点。
- 鼠标悬浮与键盘/手柄聚焦使用同一层级的视觉反馈。
- Hover、Focus、Pressed、Selected、Occupied、Confirmed 和 Disabled 必须可区分。职业或出生点被占用等关键状态应同时使用文字、图标或描边，不能只使用颜色。

页面切换使用约 0.18–0.25 秒的淡入与轻微位移。开始新切换前取消旧 Tween，避免快速输入导致页面叠加。未来启用“减少动态效果”后可直接写入最终状态。

UI 文案保持简短。无效操作在对应控件旁显示原因，不用长规则说明代替状态反馈。

## 开局数据与兼容契约

前端使用强类型草稿，不在编辑期间直接改写运行中会话。

`SessionSetup` 保存：

- `mode`
- `human_count`
- `bot_count`
- `players: Array[PlayerSetup]`

它提供 `resize_slots(human_count, bot_count)`、`validate() -> PackedStringArray`、`duplicate_snapshot() -> SessionSetup` 和 `to_legacy_player_data() -> Array[Dictionary]`。

`PlayerSetup` 保存：

- `slot_index`
- `display_name`
- `control_kind: HUMAN / BOT`
- `profession_type`
- `starting_region`

`GameManager.begin_local_session(setup, seed_value) -> Error` 先校验草稿，再确定本局随机种子、按该种子重建牌库，最后提交深复制快照；因此日志中的种子与实际开局牌序一致。`prepare_local_session(setup) -> Error` 仅负责快照提交，供已经完成运行时重置的兼容入口使用。`GameManager.get_active_session_setup()` 向地图初始化提供快照。

为保持当前地图、测试和自动对局兼容：

- 准备成功后仍生成现有 `GameManager.player_data` 字典数组，并保留 `is_bot` 控制类型。
- `main_map` 优先读取强类型快照；无快照时回退到 `player_data`。
- 职业 ID、地区枚举和 `MapSection.出生点坐标` 仍是规则层权威，UI 不以中文提示文案反向解析规则。
- `PlayerClass` 只记录 `HUMAN / BOT` 控制类型；本版两者不产生玩法差异。
- 连续开局时必须替换而非叠加草稿、快照、资源重置和信号连接。

前端对外发出类型明确的 `mode_requested(mode)` 和 `local_setup_confirmed(setup)`，并预留确认、返回、无效操作与页面切换的 UI 音效信号。页面通过前端主壳和定向信号通信，不新增通用 EventBus 或全局 UI Autoload。

## 页面组织与适配

前端主壳管理页面栈、草稿生命周期、返回语义、焦点恢复、切换动画和模态。首页、模式选择、人数配置、玩家配置、阵容总览、加载、确认模态和短提示只展示数据并发出用户意图，不直接切换游戏场景或重置牌库。

前端布局使用容器、锚点、最小尺寸和安全内边距，不以 `2560 × 1600` 绝对坐标堆叠为主。保持当前项目全局拉伸策略和对局 HUD 不变，前端在常见 16:10、16:9、4:3 和超宽屏上使用安全内容区，不强行拉伸核心内容。

## 未来接口与本版边界

本版只预留以下接口，不实现对应系统：

- 网络游戏模式请求。
- 教学模式请求。
- UI 缩放变更 `ui_scale_changed`。
- 减少动态效果 `reduce_motion_changed`。
- UI 音效开关 `ui_sound_enabled_changed`。

本版不实现机器人 AI、多手柄分配、网络联机、教学关卡、完整设置页、最终静态美术，也不重排对局内 HUD、改写 Demo 内置说明或改动玩法数值。
