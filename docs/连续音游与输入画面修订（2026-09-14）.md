# 连续音游与输入画面修订（2026-09-14）

本记录对应用户最新十二项问题和已确认修订方案。当前交付是工作区工程；不制作美术 ZIP，不进行真实麦克风录制。历史测试不作为本轮结论。

## 已接入的修改

- 五个表演音游改用 `Audio/rhythm-v4/` 连续授权原声。正式音频与 9 月 9 日授权派生片段逐字节一致，未插入回应静音，未变调、拉伸。鼓盆歌仍用原有示范—复现录音和三轮规则。
- 点击、换侧与长按起点：误差不超过 75ms 为优、180ms 为良；收尾为 100/220ms。优计对应部分 100%，良计 80%。长按仍分起点 30%、保持 30%、收尾 40%；保留部分分数、空击扣分与一次输入最多一个事件。新增优良失局部特效、错误短提示及结果计数。
- 花鼓戏、提琴戏撤下旧合成反馈，改从各自授权现场录音提取短片段，独立低音量叠加。保持过程中不循环短人声或弓声。它们是混合现场录音片段，不是独立声部分轨。
- 输入设备提示原位更新；偏好配置按路径缓存。切换设备不清空其他来源的按住状态；鼠标移动须在 180ms 内累计超过 16 屏幕像素，键盘或手柄仍按住时忽略纯鼠标移动。汉剧左鼠标键选左灯、右键选右灯，键盘和手柄直接选侧。
- 神农的宿主输入测试覆盖 D/右箭头交叠、移动鼠标、右键跳跃、真实移动按钮及画面外释放。首次审计猜测的“宿主遍历改写关内焦点”并不符合当前代码：宿主本就跳过任务容器。实际整改聚焦提示重建、设备切换与输入归属。
- 兴山六角色及共享人物从完整原稿重新明确裁切；神农六角色修正跳跃、下落、落地、采药姿势的邻行残片。保留既有八帧跑步原色与细节，不再压成 20×24。源稿、原导出备份和逐帧矩形见 `v3/source/crop-repair-v4/manifest.json`。
- 准备页标题居中并加双线；教学显示青绿顶条、边框和底部当前动作，正式改暖金边。正式前居中 3、2、1，开始提示约 0.45 秒。新增生成的“楚物TV”台标，修正技术底和浅色字被误抠除的问题。
- 剪纸四处纹样、30 秒。新增约 306 逻辑像素锯齿叶心，与镂空共用几何。最后合法闭合后停操作计时，纸屑脱落约 0.6 秒，再揭纸、结算。暂停冻结收尾，完成只发送一次。
- 神舟三道护送：7200 单位，初速 200，范围 100–320，加速/制动 180/360，单道 0.32 秒，35 秒上限；14 组障碍含两段错位窄隙。障碍船重新生成较宽短驳船，保留原稿比例，水面投影提速，楼台不作为碰撞体。
- 人物画面视口改为收到状态更新才渲染，准备、暂停、结果收尾后的静止纹理不持续重画；按键图标缓存样式。

## 验证状态

已运行的专项包括：输入配置 8 项、实际 Host 混合输入与提示复用 3 项、分级判定 19 项、动作/拼图/剪纸/推车/护送 13 项。后续增量及完整验证以最终日志为准，不能把这里的数量相加当作完整 Beta 总数。

`artifacts/input-revision/after-wall.json` 使用实际墙钟测量连续帧，三个分辨率各 180 帧，预热后连续注入键盘、鼠标及手柄事件：

|---|---|---|---|
| 1280×720 | 5.833 / 7.696 / 8.278 | 0.467 | 0 / 0 |
| 1920×1080 | 4.577 / 4.695 / 4.902 | 0.405 | 0 / 0 |

这是本机 D3D12 当前场景的短时测量，不代表全场景长时间性能。修复前采样未成功生成可用报告，不能给出可信的前后改善百分比。较早 `after-input.json` 使用 SceneTree delta，最终以 `after-wall.json` 为准。

当前工程截图在 `artifacts/input-revision/screens/`；检查包括三尺寸准备页、居中倒数、教学、神农奔跑及跳跃。六位神农新导出姿势逐张检查，完整画面和实际连续动画仍与程序结论分开。

## 尚待听审和用户反馈

五关 v4 提示时间点为明确可编辑的候选编排，**尚未完成逐句实际听审，不能声称每个时刻已准确贴合真实节拍**。现场短反馈的听感、音量遮盖也未验收。音频台账诚实记录 `listening_review=false`；连续文件和哈希检查只证明未再人为断声。开发试听页由 `tools/preview_heritage_charts.py` 更新，便于逐事件听审。

本轮尚无用户对新台标、第四刀、提速护送或连续音乐的试玩认可。实际截图不等于手感验收。首轮画面采样过程中 Windows 输出设备曾被系统失效一次（WASAPI）；该段不能用于听审结论，设备故障日志保留。

## 重建入口

- `tools/repair_avatar_crops_v4.py`：确定裁切与技术底整理，不重绘角色。人物资源和神农资源 CLI 重建入口已自动调用此修复，避免再次导出旧等分切图；单独调用旧函数时仍须执行修复。
- `tools/export_revision_ui_props.py`：从已存生成原图导出台标和短驳船，保留原稿。
- `tools/build_continuous_music_v4.py`：连续音频、候选事件、教学切段和短反馈来源。运行会更新音频哈希，运行后须重新导入；测试和采样期间不要同时重建。
- `tools/capture_revision_host.gd`：当前宿主真实渲染截图；不注入成功。
- `tools/benchmark_minigame_input.gd`：当前宿主设备切换墙钟采样。

## 本轮最终程序验证与实际渲染

- `verify_beta.ps1 -SkipCleanImport` 最终通过 **688 项测试、41887 项断言、9 局模拟冒烟**；包括导入、主场景启动和真实指针前端流程。最终运行复用导入缓存；本轮首轮已经做过干净导入，首轮的过时教学时长、版本和评分断言随后修正。最终日志在 `artifacts/verify/`，九局为 2/3/6 人各三种策略，均由本次重新生成。
- 完整验证启动后的神舟碰擦恢复修订另通过 **17 项、1504 项断言**：普通路线可达、全程最高速不能通过、两次失误仍可补救、六角色规则一致。恢复不再自动跳到空道，也不向前增加距离；停回障碍前保留重新判断和变道空间。不能把完整 Beta 日志当作已覆盖这项最后的修订。
- 六音游使用当前音频时钟和普通输入事件实时走完，均通过；花鼓戏、提琴戏覆盖长按暂停续接。采样中读回 GPU 并保存 PNG 会延迟驱动输入，因此该轮少量漏击不作为正常运行性能测量。关闭截图后丝弦再次完成，24 优、0 良、0 失、0 空击。记录分别在 `artifacts/input-revision/music-with-captures.json` 和 `music-no-captures.json`。这些是自动输入，不是真人手感验收。
- 神农六角色 720p、美食角色 1080p/1600p，共八次正常输入路线均约 33.0583 秒、0 跌落。实际图像检查包括左右腿经过姿势、起跳和完整头部；报告在 `artifacts/input-revision/shennong-route/`。
- 剪纸六角色实际指针完成四处轮廓并等待脱落、揭纸结果；检查成品四处全部镂空。驱动执行速度不用于估计真人 30 秒难度。结果在 `artifacts/input-revision/paper/`。
- 兴山使用连续原声和普通输入完成全部 16 个山口，包含暂停、窗口调整和结算画面；完整角色头饰已显示。主鸟规则和评分未改。
