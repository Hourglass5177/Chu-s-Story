# 传承小游戏体验复盘与重设计

日期：2026-09-10。性质：**源码复盘、案例调研和下一版设计提案**，尚未改动 Godot 玩法。用户本轮实际试玩反馈优先于 9 月 9 日的实现报告。下面的新玩法、时长调整和界面方案是待讨论的设计，不是已经通过的成品。

## 1. 这次究竟重做哪些关

用户首先确认炼丹、兴山民歌、糖塑通过，神农太简单，下堡坪看不懂，其余新做关卡不合格；随后明确剪纸、西塞神舟会、黄梅戏也保留玩法，并将鼓盆歌作为玩法通过、缺素材的例子。

| 处理 | 关卡 | 边界 |
| --- | --- | --- |
| 保留玩法，共 7 关 | 夏氏炼丹术、兴山民歌、天门糖塑、鼓盆歌、鄂州雕花剪纸、西塞神舟会、黄梅戏 | 不借统一改版擅改操作、难度和评分；补媒体、表现、共用界面后做体验回归 |
| 调整关卡挑战，1 关 | 炎帝神农传说 | 保留固定物理尺度和移动跳跃，重新编排路线 |
| 重做，共 7 关 | 下堡坪民间故事、董永传说、老河口丝弦、撒叶儿嗬、荆州花鼓戏、汉剧、提琴戏 | 同时重新设计玩法组织、教学、画面、声音与输入体验 |

“保留玩法”不等于素材、文化细节和所有设备体验已最终验收。尤其兴山路线与乐句的贴合、黄梅戏采集设备兼容性仍需各自验证，但不能因此推翻用户已认可的玩法。

## 2. 上一版为什么失败

责任在设计落地和验收方式。用户已经提供了六段授权视频，不能把已有录音的关卡不好玩归咎于用户没找够素材。

| 已核对的实现证据 | 玩家遇到的问题 | 下一版必须改变的做法 |
| --- | --- | --- |
| `tools/build_heritage_charts.py` 先用 `linspace` 产生 14/18 个等距候选，再在附近找能量峰；长按固定 1050 ms，休止固定 800 ms | 音乐在播放，但操作没有可理解的乐句关系。音量峰也可能是伴奏、杂音，不能代表应该接唱或落步 | 自动分析只能辅助定位；每个正式事件必须有可回听的声音依据及完整前后文 |
| 五个音乐控制器主要设置 `instrument` 和文字，实际教学、舞台和反馈集中在 `heritage_performance_task.gd` | 几个纸人站在同一空舞台，玩家反复猜什么时候按；名称不同，感受相近 | 共用时钟和判定，分别制作每关的表演场景、教学和动作关系 |
| 音乐教学只检查按过几次、左右都用过，或持键超过 0.65 秒；示范是另一套 0.7 秒提示音 | 会按按钮就被认为学会了，正式音乐里的提示却没有教过 | 教学使用正式关卡同一种声音、动作和判定，必须亲手完成目标动作 |
| 输入反馈只有命中布尔值、“接上了 / 下一句再加入”和通用短音 | 不知道抢拍、晚拍、方向错还是收尾错，也不知道是否真的按到了 | 输入立即驱动身体/器物；判定另给具体原因，错误和未输入都要有可见结果 |
| 上次运行截图中的人物很小，大片空背景；共用人物没有眼神、手型和清楚的身体朝向 | “看演员准备”只是文字要求，画面没有足够信息让玩家做到 | 先画出能辨认的准备、发力、接触、收势，再增加装饰；关键手脚和器物占画面主体 |
| `HeritageStageTask` 直接自动示范、倒数；已学会后只有约 2 秒倒数可点重学，进入正式关便禁用 | 进入得突然，想弄明白时已经开始扣时间 | 加稳定的准备页、练习入口和主动开始；暂停可查看操作 |
| 宿主有一套说明与进度，关内又有文字、校准和重学；字体有窗口坐标与逻辑坐标两套尺度 | 注意力在边角与舞台来回跳，操作文案小、目标和输入分离 | 共用界面只留必要信息，操作提示靠近动作；按实际屏幕像素验收文字 |
| 下堡坪约 12.3 秒讲完四幕；图卡主要是人、牛、洞的几何组合；固定顺序乱排再交换 | 尚未认清人物、牛与洞的关系，就要做一个规则不明显的排序题 | 先把故事因果演出来，让玩家的操作成为事件的一部分 |
| 神农同一套台阶连续上升、仅两处小障碍；旧自动操作者约 9.97 秒到终点 | 可达性修好了，但几乎只剩向右跑和重复起跳 | 给短跳、长跳、停步与重新起跳不同用途，按实际有效游玩时长设计路线 |
| 董永主要是推住前进，到桥区检查速度是否超过 112，越界立即退回 | 没有看到失稳的过程，容易理解为踩到了一条隐藏判定线 | 让坡度、惯性、车身晃动和制动距离提前暴露风险 |

旧自动操作者使用普通 `InputEvent`，但会读取谱点、平台、目标值和故事答案。它证明了这些已知答案存在一条通路；它没有证明玩家能从音画中推导出答案。534 项测试和自动满分都不能抵消此次不合格的真人反馈。

本次查看的是当前源码和上次留下的运行截图，不冒充本次重新操作了全部关卡；也未完成录音逐句听审。

## 4. 共用体验先改什么

### 4.1 准备、练手、正式开始

首次进入：一句目标 + 实际操作图标 → 一次完整示范 → 玩家完成同一个小目标 → 自己按“开始”。后续默认选择“开始”，旁边始终有“练一下”；不再自动抢跑。操作教学完成记录按新版本保存，故事正文仍保留。

每个教程只教下一步：短音关先接一次；双输入关先左右各一次，再完成一个真实小句；长按关必须成功起音、保持、松开。按键次数不再作为学会的证据。出错只重播这一小段，配明确原因，不把整套教学从头再来。

正式挑战暂停菜单提供“继续 / 看操作 / 设置 / 退出”。看操作冻结当前挑战，展示操作说明和无判定示范，不清空当前得分、不重启正式音乐、不返还本次成本；重开仍按原正式事务。图鉴练习可以自由重试。主动退出仍先结算再直接返回。

### 4.2 画面与 HUD

准备页负责完整说明；正式游玩只保留：关名、剩余时间、一个有明确定义的目标进度、暂停。校准、减少动态、辅助提示放进设置。单次操作提示贴近手、脚、弓或车，避免把“下一句再加入”放在远离角色的左上角。

目标以 1280×720 的实际显示为起点：主提示约 24–28 px、辅助文字至少约 18 px、按钮有效高度至少 44 px，再检查两种大尺寸。不是在 2560 基准视口设置 18 号字就算达标。核心舞台尽量占有效内容高度约 75%，输入区有可见边界和按下状态；界面容器和游戏逻辑坐标分开缩放。

人物需有明确轮廓、朝向、眼神和接触物。舞蹈放大腰以下，提琴放大持琴与弓，丝弦放大右手与琴面，花鼓戏突出主唱与参与者的关系。每关有自己的构图与主色关系；共享字体、按钮和线条风格，不共享同一张空舞台。原卡牌美术不覆盖。

输入立即有响应，即使没得分也要看见自己做了什么。成功使用动作完成 + 短反馈声两种通道；错误用偏早、偏晚、错侧或收势不齐的动作，辅以短提示。音乐关不使用冻结音乐时间的打击停顿，不用屏幕震动替代手脚动作。

### 4.3 音乐提示与判定

建议**新手默认开启必要的视觉辅助，允许主动关掉**，替代上一轮“正式关一律撤箭头”的限制。这是本次明确提出的设计变更。辅助不是铺满屏幕的下落谱：只围绕当前角色显示下一动作、接入位置与长按结束；等待与轮到玩家必须明显不同。

每个动作至少有“看得见下一步 → 准备 → 执行 → 回到待机”四段。初始可用约 0.8–1.2 秒前视范围试排，最终由乐句间隔决定；短密句可提前整组预告，不能把每拍都塞进同一提前量。长音起点、维持、收尾各有不同形状；音高变化不等于要求换手。

原声保持连续、不变调；操作音单独响应。具体音色需混音试听，不再五关同一声电子提示。没有独立声部时，不能宣传玩家“补上了录音中缺失的一件乐器”；演员和操作音承担参与感，混合原声仍完整。

当前五份 v1 谱面保留作历史技术样本，不能继续作为正式编排的底稿自动扩展。每关先挑 8–12 秒，在原速下回听并记录“为什么这里要按、玩家凭什么提前知道、后面怎样收”。不适合的切片换版本，不强行拉伸、不要求用户重剪。

## 5. 八关具体设计

以下时间为编排预算，不是已经从录音确认的时间码。完整音乐关仍约 30–45 秒；正式事件数量由可辨认的乐句决定，不先定均匀密度。

### 5.1 下堡坪：从考排序改为“牵牛入画”

**体验目标：** 玩家讲完后能解释牛为什么到这里、为什么住进洞、为何洞叫水牛洞。先把这三件事做清楚。

推荐同一个动词贯穿全关：**牵牛到合适的位置，让画面接着发生。** 不再抽出四张卡，另外教授选择、交换、提交三套操作。

| 场面 | 玩家看见什么、做什么 | 操作后的故事变化 |
| --- | --- | --- |
| 开场 | 明确字幕“下堡坪·马宗岭的一则传说”；士兵拉着犁，田垄只缓慢延伸；旁白交代缺粮、耕田费力 | 先展示问题，随后出现调来的耕牛，绝不让人物名字代替画面动作 |
| 牛来助耕 | 提示“把牛牵到犁前”；拖牛到犁前的连接位置，键盘/手柄选择牛后选择目的地并确认 | 绳套接上，牛走、犁动、田垄延伸，士兵松手；同一个士兵与牛保持外观连续 |
| 洞中安置 | 转至放牧回程；旁白说明发现干燥的洞穴，镜头先表现泉水、洞口与后方透光 | 玩家将牛群引入洞内空地，牛群安歇；前洞和后洞的位置关系在这一幕就建立 |
| 后洞离开 | 旁白明确战后有牛从洞尾逃出；前洞被来军占据，后洞透光仍在 | 玩家引小群牛走后洞，镜头跟随离开；最后回看洞口并出现“水牛洞”名字与简短收束 |

交互采用宽裕目标区、拖动预览、可撤回与放错回弹；无错放扣血和第二次提交即失败。后两幕最多同时出现两个有意义的目的地，不能用三个荒唐干扰项做常识选择题。正式版的牵引、路径与洞内构图是游戏化展示，不宣称是实地测绘。

**时长取舍：** 建议把阅读/旁白与玩家操作预算分开；操作合计先试 25 秒，首次完整观看约 40–55 秒。旁白停顿及结果演出不偷扣操作时间，已读字幕可点击继续，必要故事不直接跳过。此项有意放弃原来“整个故事必须 30 秒结束”的限制，避免再次为了时长牺牲理解。

风险也要正视：它是轻叙事互动，挑战不如节奏关。首个分镜样板如果依然只是点亮目标、玩家讲不出因果，就需要重写场景；不能靠加一道结尾选择题掩盖。

来源保留 [湖北日报《“洞”人故事》中的水牛洞传说](https://news.hubeidaily.net/pc/c_2714369.html)。不补造神牛、神迹或虚构当地说书人。新旁白分句重新录制/合成，不沿用当前高速四句版本。

### 5.2 炎帝神农：一条需要控制起跳和落点的采药路

保留移动、跳跃、短跳、离地宽限和输入缓冲。正式目标仍为采到终点药草，无额外计分道具门槛。路线分成三个能辨认的小环境，熟练操作目标约 25–32 秒，首次正常操作约 32–40 秒，45 秒上限为失误保留空间。这是待实测的目标，不能靠摆到某个总长度就宣称达到。

| 路段 | 新决策 | 安全安排 |
| --- | --- | --- |
| 林下入山 | 先短跳过低障碍，再越过较长沟；反复同一种起跳时长不适合两个落点 | 首个低障碍后有平地，沟底可快速恢复；落点提前完整出现 |
| 溪涧连跳 | 两次跳跃之间有短平台，必须落稳、再起跳，避免全程按右直接掠过 | 平台宽度先试 110–150 逻辑像素；短平台前后各有宽落点；不新增蹬墙与冲刺 |
| 石坡采药 | 先看落石提示，选择经过的时间；最后组合一次短跳、一次登高 | 一个固定、清楚的落石区域，碎石/阴影至少提前约 0.9 秒；等候点无伤害，终点前可喘息 |

最大跳高约 96，必经上升高差先用 45–70（不超过约 72 的 75%上限）；同高水平跳距约 200，高差会减少水平余量，不能分别把最大高度和最大宽度一起使用。所有沟宽用实际轨迹验证，再留至少约 20%余量。只给三段入口设置检查点，不再每块平台都自动刷新；一次失误尽量只重走 2–4 秒。

低顶障碍若用于短跳，须先完成实体顶部/侧面碰撞并有独立验证，不能在当前只处理平台顶面的代码上直接画一个屋顶。首版可先通过短落点与长沟形成差别。新增落石必须先单独示范，再和跳跃组合，不能首见就撞。

### 5.3 董永：能感觉到重量的推车过坡

保留“鹿车载父、推与刹车”，但重新做运动和路况。画面主体是一辆有车架、轴、车轮、坐席和把手的小车，父亲稳坐，董永的手始终连接把手；鹿车不是鹿拉着的车。

先在安全平地试“推起来 → 松开还会滚 → 刹住”。正式约 24–28 秒：缓坡推车、短陡坡保留动量、下坡提早收力、桥前制动、稳稳过桥。上坡松力会渐慢甚至轻微回退，刹车可稳住；下坡松力仍会加速，因此刹车有真实用途。推与刹同时按仍刹车优先。

速度不藏在某个数字阈值里：轮辐转速、步频、车身倾角与下坡远景共同表现。桥前较远就看到桥和慢行提示；车身开始轻晃时还能刹住。只有持续失稳才停在危险前的安全处，演出明确“收稳车再走”，不瞬移且不伤害老人。第一次小失误不能直接耗尽全关时间。

鼠标使用明确的“收车 / 推车”两个大按钮（均为左键按住），键盘用左右方向键，手柄用左右肩键或可配置等价键；文案不再写有歧义的“右键推车”。普通推行、松力、制动、恢复都要有不同姿势和车轮声音。

### 5.4 老河口丝弦：看得懂轮次的合奏接力

这是第一首音乐样板的推荐对象：已有合奏录音，单输入，容易把“我什么时候参与”单独验证清楚。

镜头围绕小乐班，玩家三弦在近景。教学先让另一位乐师准备、奏出一个声音，再把视线和动作明确交给玩家；到接入点按一次，拨弦动作与琴面震动即时出现。辅助小提示位于玩家拨弦手旁，不远离器物悬一个无含义的半圆。

正式三组：单拨接入建立预期 → 提前展示双拨手势并接两下 → 已学过的单/双拨之间出现有声音依据的等待。每组末尾给一次合奏收句反馈；等待期间其他乐师仍在演奏，不能全场僵站。它考轮次预判，与鼓盆歌“先听完一串、再完整复现”的记忆玩法区分。

错拍时右手仍拨弦，但会相对其他人早/晚，短文字说明原因；下一句自然回到乐班。单次错失不清空整段成果。实际录音不能辨认的“乐师轮奏”仅作游戏舞台编排，不把混合录音虚构成已分轨的真实轮奏。

### 5.5 撒叶儿嗬：脚下有重心的双步合舞

排练场景，领舞在前，玩家稍靠后，两人朝向一致。近景必须看清两只脚、膝盖和身体重心。镜头不切、左右含义不随角色转身改变。

教学：左脚抬起预备 → 在落点按左；右脚同样一次 → 跟成一个完整短句。正式先交替，再同侧重复，最后加入一个已经示范过的停顿。玩家按键后脚要真的离地/接地、身体随之承重；当前只改直线腿角度的实现废弃。

左/右脚下有形状不同的脚印辅助，按压状态与下一步预备分开；开启辅助不额外扣分。错侧会迈错脚，早晚会与领舞错半步，均不让整队停舞。小句结束恢复队形，玩家能看见自己重新跟上。

当前电视演出视频可继续用于鼓声与服饰参考；连续脚步示范值得补，但在缺少完整动作证据时不能自称复原传统舞步。舞蹈简化仍注明传习场景，不把丧仪背景改成搞笑蹦跳。

### 5.6 荆州花鼓戏：听完这一句，接上自己的应和

主唱居画面一侧，玩家与帮腔队伍在另一侧；必须一眼分清“现在听谁”和“接下来谁出声”。近景让吸气、张口、收手能看见。

首个样板只用一组清楚的“提示 → 等待 → 短接声”，成功后才加入长声。长声采用按住开口、松开收声：角色胸口和袖口保持动作，旁边一条短、明确的收束提示呈现还要保持多久；结尾提前显示收势。正式挑战的差别来自长短与句间留白，不靠同一组固定 1050 ms 长按。

提前开口听到自己的短反馈并看到抢唱；长声松早则队伍还在收束，拖晚则自己最后闭口。避免只有命中时才动嘴，未命中按键像失灵。

《站花墙》现有段先回听。只有确认了实际主唱/帮腔关系，才能将对应时间段写成真实帮腔；若所选段没有可用的应和，先在现有九分钟原片中重新选段，再考虑补录音。素材没有提供之前也不造“嘿、嗬”唱词充数。核心原型必须有一组成立的声音关系，不能用美术掩盖这个缺口。

### 5.7 汉剧：把抽象换边改成“台口追光”

推荐重做玩家身份：玩家控制一束追光，让它在演员换位和定点亮相时到位。单键换左/右仍可保留，但“为什么换、什么时候不换”从舞台事件中获得意义。

先在左台口稳定照亮；演员转身、迈步到右台口，玩家在到位时切灯，接住亮相。下一句演员只伸袖或转身、并未换台口，玩家应保持追光；这两种情况必须在教学中分别见过。正式顺序是稳定停留 → 明确换位 → 同侧身段与换位组合 → 一次提前预告的快速来回，最后收光。

光圈始终显示当前照到哪里，目标台口轮廓和演员脚下标记支持预判。乱切时错误地照到空台口，漏切时演员到位而光没跟上；错误下一次换位即可恢复。评分检查切灯时机与停留中的无效切换，不回退成“到点恰好在正确侧就给分”。

追光调度是现代游戏化舞台工作，不宣称是汉剧传统技法；两台口不贴西皮/二黄标签。优先沿用《丛台别》现有原声，但身段须取可辨认的动作参考。若短样板仍像交通灯反应题，先推翻这一方向，不扩写四十秒谱面。

### 5.8 提琴戏：运弓过程本身要可见、可控

近景以琴筒抵腰、持琴手和运弓手为主体，上方用小幅舞台远景交代伴奏关系。左右输入控制两个游戏弓向；按下起弓，按住继续移动，松开停弓。手臂、弓、弦的接触关系不能断开。

短音让弓走短距离，长音持续走到预告的收束位置；新弓方向和本弓剩余行程靠器物上的简短辅助呈现。先只练一个方向的短、短、长，再学换弓和休止，避免第一秒就同时判断方向、时间和长短。

这一关的重心是连续运动的起收，丝弦重心是轮次接入，花鼓戏重心是听唱后的回应。不能只换乐器模型、仍播放相同点头动作。若实测双向认知负担遮住音乐，备选是自动交替弓向、只保留按住与松开；这是样板失败后的减法方案，不暗中同时实现两套。

已有资料支持抵腰姿态；当前录影没有清楚运弓近景。用户此前允许游戏化推演继续有效，但该推演不能写成实录弓法。补一段清晰近景能改善动作依据，不要求先获得专业分轨。

## 6. 如何落到 Godot，避免再做成一种游戏的五层皮

选择“现有宿主 + 小组件 + 各关独立表演场景”。继续扩充 `instrument` 大分支会让五关教学和反馈互相绑死；建立全新的通用小游戏大框架则没有必要。

```text
HeritageTaskHost                     成本、返回、模态与结果保持原职责
├─ Preparation / Pause / Result      共用界面与焦点
└─ TaskRoot                         各关控制器
   ├─ Lesson                       本关真实练手目标和示范片段
   ├─ Stage                        固定逻辑坐标
   │  ├─ Characters + Instruments   各关独立场景、AnimationPlayer
   │  └─ CueView                    可开启辅助，不决定分数
   ├─ InputAdapter                 设备事件转换为语义动作
   ├─ MusicClock + Judge            仅需要的音乐关接入
   └─ Feedback                     本关动作、声音和原因提示
```

| 通信 | 数据与职责 |
| --- | --- |
| InputAdapter → 控制器/判定器 | 一次物理边沿对应一个动作，保留设备与时间戳；界面点击先由顶层处理 |
| MusicClock → 谱面调度/判定 | 原声播放位置 + 混音时间 − 缓存输出延迟；不累加画面 delta |
| 谱面调度 → CueView/动画 | `event_id`、准备时刻、动作时刻、收束时刻；显示偏移不改评分 |
| Judge → Feedback/HUD | `event_id`、结果类型、有符号误差、起点/保持/收尾分项 |
| Lesson → 本关流程 | 完成真实目标后才记录教学版本，正式成本不在 Lesson 收取 |
| 控制器 → Host | 沿用完成与返回协议，结束只结算一次 |

现有毫秒谱面保留为现场录音的时间基准，不强行改固定 BPM。新版本增加片段/乐句编号、声音依据备注、听审状态、审阅者及对应媒体版本；展示事件独立保留。未听审事件不能被构建工具自动标为已听审。

判定起点 ±180 ms、收尾 ±220 ms、70%通过先作为原型起点，不在设计阶段凭感觉收紧。按键自动重复拒绝，一次输入只处理一个事件；长按仍分起点、保持、收尾。原始误差负值为早、正值为晚，输出到调试记录；无合适事件的空击只标“当前应等待”，不牵强归给很远的未来事件。

设备输入偏移、画面偏移与谱面切点分别保存。校准为可选工具，不能用校准掩盖未听审谱面。暂停冻结三个时间域，恢复倒数不推进歌曲，持续输入有短续接窗口；不改变正式速度。更多时序依据见 [Godot 音乐同步文档](https://docs.godotengine.org/en/stable/tutorials/audio/sync_with_audio.html)。本轮未修改时钟实现。

## 7. 实施顺序与真正的验收关口

这里是设计之后的工作分解，不是本轮已执行的代码清单。

| 顺序 | 交付物 | 进入下一步之前必须看见的证据 | 实施时使用的技能 |
| --- | --- | --- | --- |
| 1 | 丝弦一组 8–12 秒原声样板 + 下堡坪第一幕交互分镜；准备/练手界面 | 未读源码的人能辨认自己控制谁、按什么、为什么此刻按；故事操作后能描述因果 | game-design-theory、game-ui-ux、audio-system、input-handling、animation-system、godot-rhythm-game |
| 2 | 神农三段路线、董永平地/坡/桥短样板 | 正常输入存在不同有用策略；少量失误可补救，持续固定输入不能通吃 | player-controller、physics-system、2d-essentials、game-feel、godot-testing |
| 3 | 将合格样板扩到完整关卡；逐项完成剩余四音乐关 | 每关至少一个完整小句独立验收后再扩时长；每关有清楚、不同的注意与操作节奏 | scene-organization、animation-system、audio-system、input-handling、godot-rhythm-game、godot-testing |
| 4 | 已通过七关补媒体与 UI；统一结果和素材记录 | 核心玩法回归，无原有通过条件变化；新媒体不改变音画时序 | assets-pipeline、godot-ui、responsive-ui、audio-system、godot-testing |

上述 Godot 技能均指 `godot-prompter:*` 对应技能。只有具体实施开始才加载相关技能，不为设计稿创建无关脚手架文件。

验收分为三条，分别报告，任何一条不能冒充另一条：

1. **程序正确：** 单调音乐时间、判定边界、长按、重复输入、暂停失焦、退款与清理、多尺寸输入映射；自动操作者仍可证明可达性。
2. **新手理解与手感：** 由未读谱面的人直接进入；至少记录第一次有效操作所需时间、第一次困惑的画面、失误原因能否说清，以及能否在下一句恢复。初轮找 3–5 人定位问题即可，不把这点样本包装成统计意义的通过率。用户的直接体验是主要设计反馈。
3. **声音与内容：** 每个音乐样板原速听审起点、收尾和提示先后；核对文化身份、器物与动作说明；合成反馈不冒充原乐器，地方传说不冒充确证历史。

神农另记录各段耗时、跳跃次数和跌落位置；故事记录能否讲出三段因果；音乐记录早/晚/错侧/收尾的分布。出现“看不懂”时优先改提示和场面，不先加宽窗口或增加文字。反复只有熟悉答案的操作者能过，样板退回设计。
