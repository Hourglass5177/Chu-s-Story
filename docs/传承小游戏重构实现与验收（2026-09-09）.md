# 传承小游戏重构实现与验收

> **2026-09-10 用户实际体验更新：** 炼丹、兴山民歌、糖塑玩法通过；鼓盆歌、剪纸、西塞神舟会、黄梅戏也明确保留玩法。神农太简单，需要调整挑战；下堡坪看不懂，另五个音乐重构关及董永的玩法、表现与操作体验不合格，需要重做。下文测试与实现记录保留为历史事实，不能据此声称整体体验通过。下一轮先做 [设计复盘](传承小游戏体验复盘与重设计（2026-09-10）.md)，素材需求见 [补充清单](传承小游戏素材补充清单（2026-09-10）.md)。

本轮按已确认的 11 项重构方案实施，保持原任务编号、独立场景、国家级非遗计分和尝试事务。以下是当前工程说明，不能替代真人试玩和音乐听审。

## 共用实现

- `HeritageStageTask`：1000×600逻辑舞台、120Hz固定步长、鼠标坐标换算、可操作练手、首次记录、重学、恢复倒数、声音与简洁剪影绘制。减少动态时取消背景滚动，保留必要动作提示。
- `HeritageMusicChart`：版本、音频路径和SHA256、结束毫秒、稳定事件ID、动作、方向、起止与提示提前量；展示事件与判定事件分开。
- `HeritageMusicClock`：播放位置＋距上次混音时间－缓存输出延迟，保持单调；暂停时冻结，恢复倒数完成后继续播放。
- `HeritageMusicJudge`：起点±180ms，收尾±220ms；长按起点/保持/收尾为35%/35%/30%；每次空击扣0.35个事件分，休止占比最多20%；一次边沿最多处理一个事件。
- `HeritageMinigamePreferences`：`user://heritage_minigames.cfg` 保存教学版本与设备校准偏移，不混入图鉴或本局资源。教学不扣正式计时；成本仍在原正式入口收取。
- `HeritageBeatCalibration`：可选跟拍校准，不改变原声速度和谱面数据。

谱面读取失败、音频缺失、哈希不匹配或持续播放中断走技术错误及原退款路径。黄梅戏原生采集与评分保持现有实现，本轮没有进行麦克风录制。

## 验证证据

本轮新增 `tests/unit/test_heritage_rework.gd`，并更新旧传承测试和UI集成测试。

- 完整 `tools/verify_beta.ps1` 成功退出：干净导入、主场景启动、两局真实前端流程、58个脚本共534项GUT/30756断言、9局模拟冒烟全部通过。入口输出 `artifacts/rework-full-verify.log`，详细日志 `artifacts/verify/`。
- 收尾修正减少动态控件的颜色/焦点、故事错位提示清理与展示动作后，追加失焦/教学中退出、缺失音乐技术错误两项测试，传承专项55项/1227断言通过，日志 `artifacts/rework-final-tests.log`。这些收尾改动未重新跑整套对局模拟；核心事务及对局规则未改变。
- 判定覆盖起止边界、一次输入一个事件、不同帧率的带时间戳输入、两次失误可补救、无操作与乱按；平台通过方向和跳跃输入走完整条路线，覆盖1280×720、1920×1080、2560×1600和中途改尺寸。
- 生命周期覆盖全部15关退出结算顺序、真实教学中退出、失焦、暂停倒数拒绝输入、窗口外松键、阻止正式挑战中重学清分重来、缺失音频在发现前走技术错误。

`tools/play_heritage_rework.gd` 是当前引擎的自动操作员：实际播放音频，经普通InputEvent入口操作，覆盖暂停与窗口调整；不写角色位置、内部得分或强制成功。它不是人类听审或体验验证。

最终汇总 `artifacts/rework-play/final-report.json`：**11/11关正常输入自动通关**，每关均执行暂停及窗口调整；花鼓戏、提琴戏在长按中暂停，并通过重新按下续接。五项谱面关均为100%；兴山16/16山口；炼丹进度100%；糖塑3/3（此前另有一次偏小后2/3成功记录）；推车零次危险停回；神农零跌落；故事先提交一次错误，再经键盘交换并正确提交。它们展示可通过的输入通路，不代表普通玩家的通过率。

原始记录为 `artifacts/rework-final-play-output.log` 与 `artifacts/rework-play/all-eleven.json`。末尾检查移除了提前50ms结算，改为等待原声实际播放结束；共用演出控制器与飞行控制器分别复跑花鼓戏、兴山，正常通关且无播放错误，日志 `artifacts/rework-audio-tail-output.log`。其后55项专项/1227断言再次通过，日志 `artifacts/rework-tail-tests.log`。

已查看当前工程的演出、平台、糖塑、故事与飞行截图。`visual-review-*.png` 是专门检查最终分镜、合奏器物和舞台预备动作的固定状态截图，仅作美术复查，不作通关证据。未进行真人手柄操作、完整文化听审或麦克风录制。

听审工具：运行 `tools/preview_heritage_charts.py` 生成 `artifacts/rework-chart-preview/index.html`，可以查看音频时间线、按稳定事件ID逐段试听、比较起止和预备提示。直接修改 `.tres` 的展示事件不会影响判定；重新运行候选谱面生成脚本会覆盖候选资源，不用于保留已经人工审定的后续版本。

导出时资源检测使用 `ResourceLoader`，兼容原始OGG被导入资源替代的PCK。源文件存在时检查SHA256，源文件哈希也由自动资源审计覆盖；导出包中原始字节可能不在原路径，不能直接把 `FileAccess.file_exists` 当作音频存在性的唯一依据。参见 [Godot FileAccess 文档](https://docs.godotengine.org/en/stable/classes/class_fileaccess.html)。本轮未制作发布安装包。

## 仍需听审与体验验收

1. 五份音乐谱面当前是音频能量瞬态附近的候选编排，尚未逐句听审。重点复核丝弦接拨、撒叶儿嗬落步、花鼓戏长应和收束、汉剧接句与休止、提琴长弓起收。不能把自动满分称为标注符合真实演出。
2. 花鼓戏混合录音中的真实帮腔声部未确认；汉剧不标声腔；提琴视频无运弓近景。用户已允许采用连续原声和游戏化动作，不在缺乏资料时编造声部/弓法。
3. 兴山的山口属于游戏化路线，后续需听审其与《下田号子》乐句起伏的贴合程度；原唱音程保留。
4. 四幕旁白为新合成普通话，需复核“马宗岭”等地名发音、故事易懂程度和排序容错体验。
5. 真人首次教学理解、手柄手感、设备校准效果与少量失误后的通过率仍需实际用户试玩记录。未宣称已达到目标首次通过率。
