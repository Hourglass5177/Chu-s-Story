# 国家级非遗传承任务技术架构（数字版）

## 2026-09-14 表现与输入增量

本节覆盖后文旧画布和操作描述，事务、成本及原生录唱边界保持不变。

- `HeritageInputProfile`声明语义动作、绑定、输入源汇总及设备识别；图标、教学与改键读取同一映射。兼容边沿只负责旧控制器接入，不给桌游菜单全局添加WASD。
- `HeritageTaskPresentation`提供`pixel_canvas_size`、逻辑舞台、背景、六身份外观和场景。详细人物关可用1000×600表现视口，不能固定压成500×300。神农源帧320×384，展示镜头和碰撞显示统一2倍，物理不变。
- `HeritagePixelCanvas`按语义动作与独立动作时间取帧，支持帧时长和非循环收尾。结果只推进短暂表现时钟，不能继续玩法、音频或重复结算。
- 教学版本4，跳过不写完成；暂停/失焦/退出确认冻结音乐、角色和判定。正式主动退出先完成事务再发返回；长按续接与异步回调按本次运行隔离。
- 三幕拼图使用`story_puzzle_catalog.gd`和BFS盘面库；纸样使用`paper_cut_pattern.gd`与三段共享几何；董永道路采样同时供运动和接触；神舟`shenzhou_escort_route.gd`检查连续路线及扫掠。
- 六节奏关使用音乐时钟、带时间戳输入和独立图形/动画事件。新v2短句混音和谱面保留EDL及哈希，音频听审状态单独记录，不能从有效JSON推断听感。

本文说明 Beta 0.5.0 传承任务的职责边界、运行时事务和扩展约定。玩法规则见《国家级非遗传承任务设计（数字版）》，本文不重复每个小游戏的关卡设计。

## 一、系统边界

传承任务分成四层：

```text
国家级非遗 Resource
        │ inheritance_task_id
        ▼
HeritageTaskManager ── 本局状态、成本、次数、成功解锁
        │
        ▼
HeritageTaskHost ── 封面、暂停、退出、结果与清理
        │
        ▼
HeritageTaskBase 的 15 个独立场景 ── 只计算各自玩法
```

- `ResourceManager` 继续管理牌库、手牌、转移限制和有效非遗视图。
- `HeritageTaskManager` 只管理任务目录、本局传承状态与尝试事务，不承载小游戏规则。
- `HeritageTaskHost` 负责统一界面与生命周期，不决定任务成功条件。
- 每个小游戏有自己的场景和控制器。共享基类只提供输入、时钟、暂停、结果与确定性随机源。
- `DiscoveryManager` 只保存小游戏图鉴发现，不参与对局计分。
- 系统沿用 `InteractionCoordinator` 和 `TurnManager` 的模态机制，不新增通用事件总线。

## 二、任务定义与运行时数据

### 1. HeritageTaskDefinition

每项任务由一个只读 `.tres` 定义，放在 `InheritanceTasks/Definitions/`。稳定 `task_id` 与国家级非遗 Resource 的 `inheritance_task_id` 一一对应。

当前定义字段如下：

| 字段 | 用途 |
| --- | --- |
| `task_id` | 稳定任务 ID，用于存档、图鉴和测试 |
| `display_name` | 任务名称 |
| `heritage_name`、`region` | 对应非遗与游戏地区 |
| `hook` | 任务封面的一句目标 |
| `instructions`、`control_hint` | 操作说明与输入提示 |
| `cultural_link` | 玩法与非遗内容的联系 |
| `duration_seconds` | 任务时长 |
| `task_scene` | 独立小游戏场景 |
| `microphone_required` | 是否必须使用麦克风 |
| `music_chart` | 可选 HeritageMusicChart，绑定原声、哈希与毫秒事件 |
| `reference_video_path` | 经授权的派生示范视频路径 |
| `reference_audio_path` | 经授权的派生参考音频路径 |
| `reference_analysis_path` | 参考音高、节奏等分析数据路径 |

定义只保存静态内容。玩家是否传承、何时尝试、任务结果和图鉴状态都不能写回 Resource。

### 2. HeritageTaskRunContext

任务场景只接收一份运行上下文快照，其中包含任务 ID、玩家与卡牌引用、会话代次、回合代次、独立随机种子和运行模式。练习模式使用 `practice_mode`，自动测试可以注入固定结果或替代服务。

小游戏的随机数来自上下文中的 `RandomNumberGenerator`。种子由单局种子、任务 ID 与尝试序号派生，不能消耗正式对局的世界随机序列。

### 3. 结果类型

`HeritageTaskResult` 使用五种终态：

| 状态 | 规则结果 |
| --- | --- |
| `SUCCESS` | 解锁该牌，保留成本和次数 |
| `FAILURE` | 不解锁，保留成本和次数 |
| `MANUAL_ABORT` | 不解锁，保留成本和次数 |
| `TECHNICAL_ERROR` | 不解锁，退还成本并撤销次数 |
| `CANCELLED` | 会话清理或外部取消；旧结果不能写入新局 |

结果可携带失败原因、显示文字、耗时和玩法指标。失败原因必须能说明玩家哪里没有完成，技术原因则面向设备或程序状态。

## 三、尝试事务

一次局内挑战按以下顺序执行：

1. 校验玩家、ACTION、卡牌归属、传承状态、精力和本阶段尝试次数。
2. 向 `InteractionCoordinator` 申请唯一交互票据。申请失败时不扣精力。
3. 记录会话代次、回合代次和任务 ID，原子登记本阶段已尝试。
4. 通过实际精力修改接口支付 1 点成本。该成本不受损失免疫影响。
5. 创建任务宿主，载入定义与独立场景。
6. 场景完成准备并进入运行态后，记录小游戏发现。
7. 收到结果时再次核对票据、会话、回合、玩家和卡牌状态。
8. 按结果提交解锁或回滚，刷新有效非遗、手牌和计分。
9. 消费交互票据，清理计时器、Tween、录音、临时节点和信号连接。

重复点击、重复结果、旧票据、跨回合回调和上一局协程都不能修改当前状态。任务成功造成总分达到目标时，也只在完整回合结束时判断胜利条件。

## 四、有效非遗视图

规则层不能各自判断“国家级是否已经传承”。`ResourceManager` 提供统一的有效非遗视图：

- 非国家级牌始终按普通规则判断。
- 国家级牌只有在 `HeritageTaskManager.is_inherited(card)` 为真时才有效。
- 未传承牌仍出现在持有者手牌区，但基础分为 0，不进入类别、地域、数量、成就和事件条件。

基础分、类别组合、地域组合、国家级数量、收藏成就、事件目标、计分详情、胜利判断和最终排名必须使用同一有效视图。国家级不可转移的限制放在手牌底层接口；界面过滤只负责提示，不能作为唯一防线。

## 五、任务宿主与小游戏约定

`HeritageTaskHost` 是覆盖在非遗详情之上的统一任务层。它负责：

- 显示任务名、对应非遗、一句目标、操作提示、剩余时间与进度。
- 创建并配置 `HeritageTaskBase` 子场景。
- 把暂停、继续、主动退出和外部取消转发给当前任务。
- 保证结果只发出一次，并在退出时释放所有临时对象。

独立任务控制器至少实现：

- `configure(context)`：接收只读运行快照并重置自身状态。
- `start_task()`：从 `IDLE` 进入 `RUNNING`。
- `set_suspended(bool)`：冻结或恢复时钟、动画与媒体流程。
- `abort_manual()`：返回 `MANUAL_ABORT`。
- `task_completed(result)`：唯一的终态出口。

任务场景不能直接修改玩家精力、手牌、分数或发现存档，也不能自行结束回合。Headless 模拟通过注入结果走同一事务，不创建任务 UI，也不等待人工输入。

## 六、暂停、指南与失焦

非遗详情持有 `TurnManager` 的 `RESUME_REMAINING` 模态租约。任务在详情上层运行，结束后回到详情；只有关闭详情，ACTION 才从进入详情前的剩余时间继续。

以下情况必须冻结任务时钟、玩法、Tween、节奏轨、视频和录音：

- 打开 F1 游戏指南。
- 打开暂停菜单。
- 窗口失去焦点。
- 任务宿主进入退出确认。

恢复时先核对会话、回合和交互票据。若对局已经结束、返回主菜单或请求已取消，只做清理，不恢复旧任务。

## 七、小游戏图鉴与开发者视角

`DiscoveryManager` 使用 `minigame` 类型保存发现。发现记录是本机共享收藏，与单局传承状态分开：

- 场景成功完成准备后才记录发现。
- 成功、失败和主动退出都保留发现；准备前技术故障不记录。
- 重复发现幂等，不反复弹提示。
- 旧存档没有 `minigame` 字段时按空收藏读取。

小游戏图鉴只在主菜单来源的游戏指南中出现。练习场景使用 `practice_mode`，不得读取或修改活动会话。Debug 构建中，指南打开时可用 `Ctrl+Shift+D` 临时显示全部图鉴；该开关不写存档，局内也不开放练习入口。

## 八、黄梅戏录音与本地评分

### 旋律容错与分项结果（2026-09-08，比较器 v3）

玩家最新一次诊断汇总为综合 59.12、两句约 63.0／55.3、全局移调约 −11.85 半音。由此能确认低八度已经被补偿，两句也未触及45分门槛；不能据此确认所有音符都被正确识别。v2 把每句音高分封顶到 `100 × 相关系数`，导致第一句仅因约0.385的相关性最多得到38.5分，此约束过于直接。

本次修改仅在比较层和结果展示层，不改原生 DLL：

- 对齐后的每对音高误差先扣除0.5个半音的容错区，再按每半音18分扣减。容忍小幅音准／识别抖动，不消除大幅错音。
- 对变化范围至少3个半音的参考旋律，使用 `clamp(相关系数 / 0.40, 0, 1)` 作为误差得分的柔性系数。相关系数不是百分制分数；达到0.40时不额外压分，零／负相关仍不能靠贴近平均音高通过。近恒定参考乐句豁免。
- 继续保留两句共同移调、有界DTW、短八度识别异常清理和独立节奏／完整度判定。60／45及10%／55%／35%的规则不变。
- `score` 返回实际综合分，不再将未通过结果强行压到59；`passed` 明确保存未经显示取整的规则结果。任务优先使用 `passed`，仅对旧注入适配器保留按总分判断的兼容路径。临界未通过的59.96／44.96分别显示59.9／44.9，防止四舍五入后看似已达到门槛。
- Debug 增加 `line_error_pitch` 与 `line_contour_factor`，可以核对每句最终旋律分的构成，不记录声音或逐帧曲线。

`UI/vocal_score_breakdown.gd` 是宿主内的只读展示组件，不参与判分、事务、发现或暂停。显示总分、权重、每句分数和三项细分；技术错误与未评分退出显示“未评分”。正文区可滚动，返回按钮保持在正文区外，长结果不覆盖按钮。图鉴练习不显示正式对局的精力返还或下回合限制。

这些参数是原型容错设置，仍需要不同音域的真人录唱校准。只有历史汇总、没有录音或逐帧轨迹时，不能精确回算玩家旧录唱在v3下的分数，也不保证再次录唱必过。

验证记录：当前 Godot 4.7.2 的全量 GUT **523/523** 通过（57个脚本，30409次断言，`artifacts/vocal-v3-full.log`／`artifacts/vocal-v3-full.xml`）。完整授权音频的采集—真实CREPE—任务结果链路约88.0分、评分约3.7秒、主线程最大帧间隔8ms；合成低八度谐波声音约98.9分。这些是固定自动样本，不是真人通过率。最后收紧结果布局、补上方向键滚动后，另复跑结果UI、传承事务UI和评分生命周期 **20/20** 通过（`artifacts/vocal-v3-layout-final.log`），包含一次实际鼠标按下／抬起返回测试。使用当前引擎OpenGL渲染五种分辨率，截图为 `artifacts/vocal-result-*.png`，由 `tools/render_vocal_result_preview.gd` 的固定测试数据生成，不是玩家唱歌成绩。本轮没有采集麦克风，也未重做干净导入或模拟批次。

### 旋律对齐与识别容错（2026-09-08，比较器 v2，历史记录）

`huangmei_melody_alignment.gd` 是纯数据比较器，由原评分器在后台调用。不拥有场景、设备、任务时钟或世界随机源，也不改原生 DLL。综合门槛 60、单句门槛 45、10%/55%/35% 的权重保持不变。

1. **分句**：在参考分句位置前后 0.60 秒内寻找最近的真实换气间隔；找不到则保留参考分句。不能把第一句稍长的尾字直接划给第二句。
2. **识别清理**：只修正不超过 120ms、两侧有连续观测且音高相差不超过 1.5 个半音的八度异常段。异常须接近 ±12 个半音；不修正句首、句尾、跨长停顿或持续错八度。参考与录唱采用相同清理，不改变输入数组。
3. **保留时间**：每句按原时间位置重采样为 96 点。超过 220ms 的未识别区间不凭空连成旋律；缺失观测不会增加实际发声完整度。
4. **单一调性**：先估计两句共同移调量，再用匹配音符作一次中位数修正。第二句不能单独变调，音高误差仍按每半音 18 分换算。
5. **局部对齐**：使用有界 DTW，偏移同时受 400ms 与句长 15% 限制；路径只能前进，步长为 `(1,1)/(1,2)/(2,1)`，中间点也计入比较，不允许跳过一段音符凑答案。
6. **反例约束**：对明显变化的参考旋律，音高分还受对齐后轮廓相关性约束，避免单音或无关旋律只因接近平均音高而通过。近恒定的参考乐句不使用相关性约束。
7. **时间判定独立**：DTW 只用于音高比较，节奏、发声时长与句间间隔仍取未变形的实际录唱，不能通过对齐免除漏唱或长时间停顿。

Debug 的 `HUANGMEI_ALIGNMENT` 只输出比较器版本、全局移调量、每句最大对齐量、匹配覆盖率、轮廓相关性与修正帧数等汇总值。不保存录音、逐帧音高轨迹或识别文本。没有玩家原始录音时，不能追溯断言某次失败究竟是演唱偏差还是模型误识别。

算法参考：[AudioLabs 音乐同步的 DTW 约束](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C3/C3S2_DTWvariants.html)。[CREPE 官方说明](https://github.com/marl/crepe)明确区分模型容量与可选时间平滑；本实现保留既有 tiny 模型，仅在比较层作保守的短异常清理，不宣称达到了人类听辨水平。

新增测试覆盖降低八度/非整八度移调、局部拖腔、前句延长、双向短八度异常、长异常与句首句尾保护、漏唱、单音、反向旋律、确定性和不修改输入；另用合成谐波声音通过实际 CREPE 提取验证，不能仅靠直接变换已提取的音高代替识别测试。授权唱段的录音—推理—任务暂停/恢复完整链路继续保留。上述自动样本不替代不同音域真人演唱的准确率验收。

本轮验证（当前工作区 Godot 4.7.2 Headless）：新增 13 项回归和全部原有测试，共 **515/515** 通过（56 个脚本，30366 次断言，约 175 秒），日志 `artifacts/melody-full.log`，JUnit `artifacts/melody-full.xml`。专项真实 CREPE 测试中，带谐波的合成低八度声音识别移调量约 −11.94 半音、综合 98.7；授权参考唱段完整音频链路综合约 85.9，评分约 2.6 秒，主线程最大帧间隔约 7ms。仅为这批固定样本的测试结果，不代表真人演唱通过率。本轮未重做干净导入、模拟冒烟或编辑器人工录唱验收，不覆盖上一节以外的发布验证范围。

### 麦克风与判定纠错（2026-09-08）

- 正式 Windows 录音由独立 `WindowsVocalCapture` 适配器采集，系统音频引擎将包括四声道在内的输入转换为 16 kHz 单声道。关闭 Godot 内置麦克风输入，避免其不支持多声道时刷错误并填静音。其他平台没有适配器时仍技术退出，不替换任务。
- 麦克风打开过程与录音、评分分开；设备未准备好时不让玩家损失演唱时间。录唱进度取实际收到的样本数，不累加渲染帧间隔。暂停时样本不进入录音，恢复后继续录满原时长。
- 权限错误、设备失联、断流和转换失败属于技术故障。数字静音、恒定直流和非有限采样不送入模型，不把“程序没录好”显示成“演唱不完整”。
- 完整度按有效发声秒数比较，不比较原始分析帧数；参考分析 50 Hz 与实际分析 100 Hz 不再造成口径偏差。
- 音高曲线按乐句时间插值，保留停顿和未发声区间，不再按剩余音高点的个数压缩时间。全曲仍只允许整体移调，不单独修正第二句音高。
- 综合门槛 60、单句门槛 45、完整度/音高/节奏权重 10%/55%/35% 保持不变。
- Debug 只输出分项数字、错误原因和阶段耗时；不保存录音或识别文本。真实麦克风检查必须与无设备自动测试分别记录。

本次验证：Godot 4.7.2 下 `verify_beta.ps1` 完整通过（干净导入、主场景、两局前端流程、502 项 GUT、9 局模拟冒烟）；新增采集回归单独复跑 8/8 通过。经用户同意，对当前四声道/48 kHz 麦克风实际采集 3 秒，转换成功、有效信号检查通过、未出现 WASAPI 声道错误，样本仅驻留内存。授权参考音频完整链路得分约 85，评分约 2 秒。此检查验证设备采集与已知样本，不替代真人完整双句演唱的准确率验收。

黄梅戏任务使用可替换的 `VocalScorer` 接口。Windows x86_64 适配器由 Godot GDExtension 调用 ONNX Runtime CPU 与轻量 CREPE 模型，返回时间、音高和置信度序列；GDScript 规则层再计算有效发声完整度、可移调音高轮廓、节奏和句间衔接。

- 模型按进程只加载一次。
- 推理在工作线程运行，结果回到主线程提交。
- 录音只存在于内存，结束或中断后立即释放。
- 系统不上传、不保存、不遥测玩家声音。
- 麦克风、权限、录音、模型或平台适配器不可用时返回 `TECHNICAL_ERROR`。
- 评分接口不评价音色、性别、方言或绝对音高。

黄梅戏录唱结束后停止扣减任务倒计时，宿主时间栏显示“评分中”。`HeritageTaskBase.is_task_clock_running()` 默认开启，仅黄梅戏评分阶段关闭；其他小游戏的倒计时规则不变。评分有独立的 60 秒技术看门狗，暂停期间不累计，超时返回 `TECHNICAL_ERROR`，不能按玩家失败扣除本次机会。

评分线程可以在指南、失焦或暂停期间完成，但结果先留在任务内，恢复后只提交一次。取消时清除待提交结果；退出确认直接终止暂停中的任务，不能先恢复并误提交缓存的成功结果。会话和尝试事务仍由管理器作最终校验。

Debug 输出 `HUANGMEI_SCORING` 分段耗时，不含录音或玩家内容。`tools/probe_huangmei_scoring.gd` 与 `test_huangmei_audio_pipeline.gd` 使用授权音频或静音样本验证实际录音收尾、后台推理、主线程响应和暂停结果回收，不访问麦克风或发现存档。

2026-09-08 验证记录：Godot 4.7.2 下首次全量 492 项 GUT、两局前端会话 E2E 和 9 局模拟冒烟通过；随后音频测试复跑暴露了参考音频被 SceneTree 计时器提前截断的问题，改为等实际音频播放结束后再采样评分，调整后连续三次黄梅戏专项测试（每次 8 项）及再次全量 492 项测试均通过。最终全量回归的授权音频链路收尾约 6ms、后台评分约 2.43s、最大主线程帧间隔约 7ms。此数据不是性能保证，也不代表麦克风或当前编辑器交互已经验收；用户报告的评分前长时间卡顿尚未在该自动链路复现。完整验证入口的导入步骤因已打开编辑器占用扩展 DLL 而失败，未把它记为干净导入通过。

原始授权媒体、派生媒体、模型、运行库、哈希和许可记录见《非遗媒体授权与第三方组件记录》。模型与运行库版本必须固定；更换模型后需要重新校准门槛，并更新固定样本测试。

## 九、会话清理与测试边界

新局、返回主菜单、终局和场景切换会统一取消活动尝试，并清空本局传承状态与尝试记录。取消时不得让旧协程返还到新玩家、解锁新局卡牌或恢复已经失效的模态租约。

自动化测试至少覆盖：

- 15 张国家级牌、15 个任务 ID、15 个定义和 15 个场景一一对应。
- 成功、失败、主动退出、技术故障和会话取消的成本与次数。
- 未传承牌在所有计分、组合、成就和事件入口中的统一排除。
- 国家级牌在出售、购买、赠送、偷取、交换和转移底层接口中的拒绝。
- 任务、详情、指南、暂停、失焦与返回链路无票据、计时器或模态泄漏。
- 固定种子下每个小游戏的成功、失败、超时和取消。
- 练习与开发者预览不影响对局或真实发现存档。
- 黄梅戏双句完整度、分句门槛、综合门槛和技术错误。

新增任务时，先增加定义、独立场景和固定种子测试，再把对应国家级牌的 `inheritance_task_id` 指向该定义。不得在 `HeritageTaskManager` 中添加按任务 ID 分支的小游戏逻辑。

## 2026-09-09：重构关的共用组件

原有 Base/Host/Manager 的事务边界保持。11 项重构关继承 `HeritageStageTask`；五项按谱演出的控制器再复用 `HeritagePerformanceTask`。鄂州剪纸、黄梅戏、西塞神舟会、鼓盆歌继续沿用原控制器。

- Stage 使用1000×600逻辑坐标、120Hz固定步长与统一鼠标转换；示范、练手、倒数和暂停恢复期间不扣正式时间。
- 教学版本与设备校准写入独立 ConfigFile，不写共享定义资源，不复用 DiscoveryManager。
- Chart 保存稳定ID、毫秒起止点、动作、方向、提示提前量、版本、原声音频SHA256及结束时间。判定与展示事件分别保存。
- Clock 缓存输出延迟，采用播放位置加混音间隔减输出延迟，并保持单调；判定不依赖屏幕图形位置。
- Judge 按带时间戳输入裁定，长按起点/保持/收尾分别占35%/35%/30%，空击每次扣0.35个事件分；音乐总分70%通过。
- Host 的主动退出出口先发结算信号，再发返回信号；普通成功/失败仍保留结果。故事结果可以回放四幕，不产生第二次结算。
- 实现与测试记录见 `docs/传承小游戏重构实现与验收（2026-09-09）.md`。旧节中的黄梅戏验收数字是历史记录，不代表本轮结果。

## 2026-09-13：独立像素表现与电视宿主

`HeritageTaskRunContext.avatar_id` 是正式职业或练习选择的快照。`HeritageTaskPresentation` 挂局部舞台、背景、封面、六套 `HeritageAvatarAppearance`、动画与锚点；定义与运行分数仍分开。`HeritagePixelStage` 只将画面绘到500×300，输入与物理继续按1000×600计算，高清文本由外层Canvas绘制。

各关提供 `get_visual_state` 或只读 `get_presentation_state`，独立 `Presentation/Stages/*_pixel.gd` 消费语义事件。五音乐关共享Clock/Judge，但保留自己的乐句教学与预备、动作、失误、恢复表现。音乐图集按身份整行采用共同裁切与比例，避免弓向变化导致琴筒漂移；董永、糖塑与剪纸另有逐帧接触锚点。

本版Judge长按权重更新为30%/30%/40%，休止对总分贡献上限20%；输入按时间戳处理且一次只消费一个事件，拒绝键盘重复。暂停冻结进行中的长按，恢复倒数后调用 `begin_resume` 建立350毫秒续接窗。显示事件不反向决定评分时间。

Host开始时先展示准备页，随后开始或重学；正式事务收费仍发生在既有入口。暂停、设置、失焦、指南及退出确认使用叠加原因，不因关闭一个面板释放其他暂停。设备校准也冻结暂停时间；真实中文字号按屏幕实际缩放计算。结果信号不因收尾画面延迟，退出仍先结算再返回。

资源索引和生成入口见 `tools/build_pixel_resources.py`。导出不包含源生成图、设计板或QA截图；游戏运行图与原始生成版本独立保存。
