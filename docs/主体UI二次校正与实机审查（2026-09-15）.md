# 主体 UI 二次校正与实机审查（2026-09-15）

本轮是在已接入美术的基础上继续修复。用户明确指出多数页面没有认真对照效果图，存在过小、偏移、重合；这些反馈成立，上一轮不能视为视觉验收。最新补充允许部分采用小游戏像素字体，现已用于部分数值及倒计时。

审查入口：[逐页截图与美术效果图对照](../artifacts/ui-main/final-review/index.html)。索引使用当前 Godot 生产场景渲染的 PNG，提供 1280×720、1920×1080、2560×1600 三种窗口尺寸。它不是新的游戏实现或网页替代品。

最新增量：按用户反馈，姓名框由 108 压到 84、职业框由 134 压到 90 个设计单位，并向下移动；人物区由 374 增至 458，撤掉上半身 Atlas 裁切和椭圆遮罩，完整原立绘等比显示。顶部改为上排“回合 / 当前玩家 / 倒计时”、下排五个等宽阶段标记，当前阶段用深橙底、浅色文字和三角标记同时识别。阶段栏仍可打开当前阶段规则。六角色和五阶段有三尺寸截图，相关 54 项测试、16190 项断言通过，日志为 `artifacts/ui-main/banner-regression.log`；阶段规则入口及 AI 四档速度另以普通指针事件验证。此次局部改动未重跑完整 Beta。

## 项目与流程理解

主体仍是湖北非遗主题的本地回合制桌游。玩家从首页配置人数、电脑难度、职业与起点，确认阵容后进入地图；依次经历准备、掷骰、移动、行动与结束阶段。积分点用于经营，精力限制行动；食物、事件、职业与研究所改变资源和选择。收集的有效非遗、类别/地区组合与成就参与最终计分。

国家级非遗的“获得牌”和“完成传承”是两步，未传承显示问号，完成后才解锁分数及组合资格。详情页是主体与传承系统的交接处。本轮只检查该入口与成本提示，不重做小游戏图鉴、准备、教学、挑战、暂停、结果或电视外框。

## 发现、修复与玩家影响

以下将源码发现、实际渲染观察和修复区分记录；“已修”指实现与检查结果，不代表作者已认可美术。

| 严重程度 | 证据与问题 | 已实施的修正及影响 |
|---|---|---|
| 高 | 源码和截图：旧 HUD 底图仍覆盖新计分底板；按钮被纵向拉伸；地图、栏位和装饰各用旧坐标 | 统一比例布局，隐藏重复旧背景；地图卷轴围住真实地图，操作按钮改底部横排。数值与当前行动区域更容易分辨 |
| 高 | 运行观察：电脑配置页新增难度行后，外框高于视口，确认区逼近屏幕边缘 | 降低出生点列表的卡片式厚内边距，保留正文大小；三尺寸下检查外框、操作区均在视口内 |
| 高 | 运行观察：城市标签相互重叠；显示“P2已选”时更严重 | 简图只写城市名，所有权放在提示与完整列表；重排展示锚点，检查任意两个热点矩形不相交。真实出生坐标不变 |
| 高 | 运行观察：AI 速度文字覆盖指南/暂停图标 | 速度保留顶部镜像位置，工具图标独立下一行；检查矩形不相交，并用普通指针输入事件依次点击四档速度 |
| 高 | 运行观察：事件提示框过高，第二选项被挤出 | 提示与倒计时分区，降低不必要的最小高度；两项选择可完整显示，多项继续滚动 |
| 高 | 回归发现：选完出生点后快速确认/返回，延迟焦点仍指向已禁用页面 | 恢复焦点前核对当前席位、可见状态和交互状态；不再向离开的页面强制抢焦点 |
| 中 | 源码和截图：多数正文过小、轮廓描边混杂；商店价格、描述长短影响按钮位置 | 思源正文与标题分层；数值局部使用像素字体；固定卡片信息区和两行效果区，按钮同底线，长内容保留提示 |
| 中 | 源码和截图：详情只有外框换皮，正文位置仍沿用旧版 | 补齐卡牌底框、标题牌与阅读底板，正文放进独立滚动区，保留完整原图 |
| 中 | 运行观察：黄石等浅色地区文字与米色底对比不足 | 只为 HUD 标题生成较深文字色，不改变地区牌面颜色与地图资源 |
| 中 | 源码：研究所缺少效果图中的选中预览；计分框缺少明确交互层 | 新增选中牌预览及详情按钮；总分区域加可聚焦的真实按钮，打开既有计分详情 |

## 实际检查与验证边界

1. 使用 Godot 4.7.2、Compatibility/OpenGL，直接实例化生产主菜单或主地图。`tools/ui_main_review.gd` 提供审查状态与截图，未用网页模拟游戏 UI。
2. 31 种页面/状态各有三档窗口截图。1280×720 和 1920×1080 继续按工程既有 16:10 等比适配，根视口图分别为 1152×720 和 1728×1080，截图不包含窗口左右留边；2560×1600 为完整原比例。没有宣称已实现全宽 16:9 重新排版。
3. 已查看各类代表画面，重点在 720 高度检查字体、重合与底部按钮，并复查高分辨率画面；不宣称每张图的每个像素都已人工检查。电脑配置、普通配置与 AI HUD 另有实际矩形边界检查。
4. 详情、职业、成就、商店、背包、研究所、计分与暂停在 2560×1600 下，经 `InputEventKey` 和指针按下/抬起事件检查 Tab 焦点及关闭。AI 速度通过指针事件循环四档；魔术择牌检查 Tab 焦点。这些是引擎普通输入事件，不是手动操作物理鼠标或真实手柄验收。
5. 审查夹具设置手牌、商店到达或结果快照以覆盖页面。事件与择牌截图不等于完整正式事务执行；正式生命周期由相应回归另查。
6. 完整 Beta 本次通过 **741 项测试、42364 项断言、9 局模拟冒烟**，见 `artifacts/ui-main/final-beta-verified.log` 与 `artifacts/verify/gut.log`。使用 `-SkipCleanImport`，没有清除共享 `.godot` 缓存。
7. Beta 启动后继续调整了出生点按钮内边距与魔术择牌排版，因此另跑最终 UI 专项：**164 项测试、21681 项断言通过**，记录在 `artifacts/ui-main/ui-regression-complete-verified.log`。随后像素字体增量另通过 **42 项测试、342 项断言**，见 `artifacts/ui-main/pixel-font-regression.log`。不把较早批次笼统表述为所有最后改动的完整 Beta。
8. 首轮 Beta 的三个焦点告警已修复。旧日志保留；首次专项中“暖金倒计时”断言已随浅色底改为文字对比度检查，快速切页测试改为在有限时间内等待过渡完成，保留焦点归属与位置断言。

使用 `game-ui-ux`、Godot UI、响应式布局和输入处理技能时，本轮落实在实际问题上：由容器处理正文与卡片流式排列；固定比例区域统一从视口计算；检查长内容与电脑配置的额外高度；装饰不拦截点击，真实控件保留焦点框；模态输入边界与已有回合暂停租约分开。美术接入则按完整效果图核对取景、边框比例与标题区，避免把任意纹理直接当成九宫格。

## 保留项、剩余限制与下一步建议

值得保留的是原博主身份、非遗牌文化图文、地图山水卷轴，以及美术交付中的金色主按钮、纸面阅读区、橙色状态牌和书本/暂停/关闭图标。共享组件和规则管理器已能支持主体闭环，无须为了换皮重写交易、回合、传承或 AI。

仍需明确区分：

- 首页目前保留四入口布局，与美术开启页的原始构图有差异；本轮没有声称像素级复刻。
- 部分原卡牌上的烘焙文字属于纸质版表达，且在小图中较细。运行时名称、效果和成本使用当前数据；本轮按要求保留原牌面，不擅自重绘其文字。
- 当前没有独立、完整的主体设置页面，只有已有偏好接口；未将其算作已完成页面。
- 对局私密信息交接、所有事件选项数量/长文案组合、结算并列/淘汰的每种视觉状态，没有逐一做三尺寸截图。现有业务回归覆盖不等同于这些画面已合格。
- 本轮没有重新做十五关小游戏视觉验收，也没有录制真实麦克风。掷骰表现没有完成逐帧和长期手感验收。
- 整体仍待作者试玩判断风格和操作感受。下一步宜先用“含电脑 HUD → 商店/研究所 → 国家级详情”这条真实对局路径评价共用样式，再按实际反馈处理私密交接与长内容边界；不应继续仅按资源数量或测试通过宣布 UI 完工。
